How to use XEON'S API

Browse active endpoints, preview their responses, and copy a URL to use an API from your own app or API client.

Browse and preview

  1. Choose an API category in the left navigation to expand its endpoints.
  2. Select an endpoint to run it and view its status and response in Quick API Access.
  3. Use Copy URL beside the selected endpoint to copy its full address.

For example, the seeded demo endpoint returns a sample todo:

GET /api/demo/example-todo/

Call an endpoint

Every endpoint URL follows this format. Replace the placeholders with the category and endpoint slugs shown in the dashboard.

/api/<category-slug>/<endpoint-slug>/

GET endpoints accept parameters in the query string:

GET /api/<category-slug>/<endpoint-slug>/?q=history

POST endpoints accept a JSON object. Use parameter names configured for that endpoint.

POST /api/<category-slug>/<endpoint-slug>/
Content-Type: application/json

{"q": "history"}

Active configured APIs and plugins are listed by GET /api/endpoints/.

Parameters and responses

Each endpoint may define required parameters. Missing or unknown parameters return a validation error. Check the endpoint configuration or response preview for details.

The dashboard preview sends GET requests without query parameters and POST requests with an empty JSON object. Use the full copied URL and supply any required parameters in your API client.

Successful GET responses are cached for 30 seconds by URL and query. Repeated requests may be faster but can return briefly stale data; POST responses and errors are not cached.

Add an API (staff only)

Choose Upload API and enter an endpoint name, category, HTTP method, public upstream URL, and parameter schema. You can also import multiple endpoints from a JSON file.

After saving, the active endpoint appears under its category on the dashboard.

Create a plugin (staff only)

Open Plugins in the dashboard or Django admin to add a Python handler. It must define handler(request) and return a dictionary. The live endpoint uses the same site and the path shown in the plugin record.

When the plugin requires its generated API key, send it in an X-API-Key header or as Authorization: Bearer <key>. The key is shown once when created; admins can rotate it.

Plugin execution is best-effort isolation, not a secure sandbox. Only run code from fully trusted admins; plugin code can access service files and the network.
